# 提醒、暂停与压缩事件

## 第六阶段独立入口

安装包注册固定router.py公共处理器，默认聊天均未开启监控。context-monitor显式调用通过runtime.py管理当前项目/UUID的monitor.json，context-scroll只登记本批保护。未开启且无保护/中断/待处理通知的根聊天不写档案。子体先按来源/agent字段排除。

router将监控开启状态传入原Hook逻辑。仅本批保护时处理压缩与整理回复，不产生400k/475k用量提醒。批次关闭后由真实事务完成依据结束保护，未完/冲突发布和待处理压缩仍维持暂停。monitor关闭不解除批次中断。

监控管理精确入口为`$context-monitor`、`开启`、`状态`、`关闭`、`本周期跳过`。蒸馏入口支持`$context-scroll`、`整理`、`查看进度`、`处理中断`。这些入口在整理线仍可提交，引用或混合长文本不当控制。旧context-scroll跳过入口保留兼容。管理skill保存真实原话，程序不冒认真人身份。

公共Hook必须由客户端审核信任。运行回执绑定store/hooks/router/runtime四个脚本哈希，只证明实际收到过本版本事件，不代替客户端当前信任状态。首次arm/on没有回执时指导审核并在后续事件检查；不宣称已经强制保护。缺身份压缩发生在begin之前时可用明确指示resolve，已有批次仍用准确ack。

prepare_hooks.py保留旧项目白名单预览，供原探针和兼容测试使用。当前正式试用由安装器合并用户级hooks.json公共入口。技能脚本默认监控关闭，用户只需在希望监控的聊天显式开启。

这是显式配置后的本地Hook规则，不是用户读取本文件就授权安装。技能显式门禁、双检查、用户放行、手动压缩不变。

## 用户已确认的试用体验

2026-11-14用户明确回复“没事，在提示里写一个要我重新发送就行了”。因此被阻止时告知：原请求尚未执行；整理完成或选择本周期跳过后，重新发送原文字和附件；不自动续接。Hook只能另存文字备份，不提供附件完整备份能力，不从备份自动重放。

这项确认替代了先前“完整保留未解决前不启用拦截”的未决要求，但不改变“附件自动完整恢复仍未验证”这个技术事实。历史报告不回写。

## 配置与停用

本技能scripts/prepare_hooks.py只生成未启用预览：

```text
python <技能目录>/scripts/prepare_hooks.py --project <绝对项目路径> --thread <准确UUID> --output <全新预览目录>
```

输出context-scroll-hook.json（enabled=false、manual_resend=true、明确项目/线程列表）和hooks-preview.json。不修改项目.codex/hooks.json或全局配置，不信任/安装/自动启用。threads可在具体配置审阅后增加其他准确根聊天ID，不能用标题或通配主题猜归属。

启用前预览具体目标、备份现有Hook配置，在授权隔离项目合并事件处理器，配置enabled=true后按宿主审核信任。不要覆盖用户其他Hook；同事件可有多个处理器，现有Hook的决策仍可能影响结果。日常或全局启用不从源码验收自动推导。

停用先把专用配置enabled改为false，下次Hook立即不读写聊天状态；再按已备份内容恢复项目注册配置。不要删除档案、blocked文字或恢复证据来“停用”。配置损坏、状态异常或周期无法核定时会提示检查/停用，不自动重建覆盖现场。

## 事件职责与阈值

| 事件 | 行为 |
|---|---|
| SessionStart | 校验根聊天与项目，首次/恢复时核对实际窗口；无数据先提示读数缺失，真实数据到达补查 |
| PreModelRequest | 只记当前模型轮次，不用于拦截 |
| PostModelRequest | 完成请求的真实total_tokens，配合根turn_context/usage证据；失败/取消不算新用量 |
| Stop | 用本轮匹配的用量/窗口补核，必要时请求一次模型续跑发送聊天提醒；防续跑循环 |
| UserPromptSubmit | 到整理线后普通工作在模型前暂停；控制消息和当前整理流程回复按下文处理 |
| PreCompact | 记录压缩turn与trigger，不主动压缩也不阻止用户手动压缩 |
| PostCompact / SessionStart(compact) | 合并同一事件的周期变更、清本周期跳过/提醒、停止续跑；整理中留中断标记 |

默认400000准备、475000整理。窗口健康开始检查，以后每增长50000再查，实际窗口改变也查；阈值跨线判断不等50k。可用窗口低于600000先给余量偏小提示，这是首版试用警示值，不是模型质量线，不自动改窗口或阈值。

用量只用最近完成请求，不把全聊天累计输入或缓存/推理重复相加。启动时可读取新task_started之前最近完成用量；Stop必须本轮匹配，不能跨压缩边界。窗口来自实际token_count，不由800k配置硬猜760k。数据缺失/异常记录原因并提示，不拿旧数据冒充新值。

当前日志适配针对已测本机版本：读取开头session_meta和末尾最多1MiB元数据。根身份需准确session_id、cwd、已知根source，子体来源/父ID/agent字段或不匹配根turn拒绝。格式变化、尾部截断可能拿不到数据，不能说支持所有未来Codex版本。当前明确线程列表以外不处理。

## 控制消息和用户回复

- `$context-scroll 整理`：允许显式技能入口，Hook不自行begin。
- `$context-scroll 查看进度`：允许查询。
- `$context-scroll 本周期跳过`：只跳过当前真实压缩周期的整理提醒/工作门槛，提示重发，不永久停用；健康异常仍可提示。
- `/compact`：允许用户手动压缩，Hook不调用它。

短句须完整匹配；在引号/长业务请求中提到示例不放行。当前已有明确启动的整理批次时，用户澄清、修改、批准需主模型理解，因此Hook只附“仅处理当前整理，不启动无关业务”的上下文约束。它不是自然语言分类器，不能单靠Hook认证“可以但改X”是否批准；实际skill仍执行第四阶段用户意图门禁。没有当前整理授权不能只凭文件进入新业务。

Stop续跑只请求发送提醒，不整理或调用工具；某些宿主会把续跑理由再经提交入口，代码只放行刚刚生成的精确提醒内容一次，不把包含示例的其他工作当控制。systemMessage是UI警告，不等于普通聊天正文；PostModelRequest输出仅诊断。Stop聊天提醒会多一次模型请求，计入用量与延迟。

## 压缩周期与中断

周期重置使用压缩事件的turn_id/trigger及必要日志marker，保存marker与实际key的对应关系；SessionStart补认也同步当前key。同一PostCompact/SessionStart(compact)不重复推进，重复或迟到旧事件不撤销本次已确认的中断。新PreCompact或新日志marker仍可补认后续压缩；身份不足明确停下，不拿旧key猜认。占用下降不是压缩证据；resume不清跳过，fork新ID是独立状态。

修订002区分“通知已经处理”与“能够证明同一次压缩”。旧marker-only的log key不能自动吸收没有匹配Pre或已登记turn身份的Post；这种组合明确待核定，清旧skip并保留修改暂停，不猜计数加一。仅有旧marker的重复也不能解除当前另一份未知暂停。

SessionStart每次入口追加独立delivery_id通知，再在锁内用当前Pre/Post/marker关联；通知ID只是投递编号，绝不记作真实压缩身份。无可靠身份的Post处理凭据也不能永久复用于后续入口。凭据的identity_known只说明该次处理是否核定；未知暂停用pause_notification区分，后一次未知不能继承前一次ack。没有更多证据时，重复缺身份入口可能再次要求指示，这是保守暂停，不冒称可以区分新旧。已证明相同turn/marker的事件保持周期、skip与已有确认。

用户可明确ack当前未知暂停后继续处理；也可在可靠新Pre/Post或新marker到达、确定新事件后，针对它记录指示。旧已知重复不会把未知暂停或它的确认改回旧key；不要求重装、删状态或自动恢复原文。

压缩后返回continue=false停止模型续跑；手动压缩同样结束当前动作。若本聊天存在未发布/未取消的整理批次，或准确属于该批的发布journal仍未结束/存在矛盾，在`.状态/interruption.json`记录候选位置、batch、进度和原因。不能仅凭state.status=published认定发布完成。store.status报告该标记及事务问题，文件操作在用户指示前拒绝，包括publish/recover，不能在压缩后偷偷继续。真正完成且无本批事务问题的关闭批次不会因此重新开放。

用户明确指示后，主模型写JSON `decision:resume_after_compaction, message_ref:<真实消息定位>, user_text:<原话>`，用store的ack-interruption --batch --instruction-file记录。它只解除当前操作暂停，不恢复旧原文、不等于批准候选，也不自动恢复半发布journal。用户若要放弃该批，记录指示后cancel；来源不足仍须说明/问用户。

不能识别压缩周期时，先停止并清除旧跳过的可用性，不猜周期身份；检查事件或停用配置。已记录整理中断者可在明确指示后ack，再核对实际范围。状态损坏不自动修复。

## 保存与验证边界

Hook状态和整理state分开，均在既有项目/聊天锁内用临时文件替换。压缩完成事件通过根身份核验后，先以独占创建方式将最小身份/marker通知写入`.状态/compact-inbox/<内容哈希>.json`并fsync，再等主锁；这一步只追加不可变通知，不在锁外改state、reminder或interruption。相同通知不覆盖，处理凭据另存compact-receipts。

锁等待仍有界（单把锁3秒，注册宿主5秒上限保持原设置），超时本次停止，已落盘通知保持待处理。锁释放不等于用户同意继续。store.status只读报告compaction_pending及具体通知/异常；后续修改会先在锁内将通知落实为周期/中断元数据，再被awaiting_user阻断，不写候选、不恢复journal。ack-interruption可直接在锁内落实通知并记录明确指示，不要求宿主再投递。通知损坏/身份矛盾保留现场并阻断；磁盘完全不可写不承诺必定落盘。真正关闭批次的通知可落实周期元数据，但不能用ack重开批次。通知及凭据用于幂等，不提供防恶意改写的签名保证。

blocked/<turn>.json保存文字、周期、附件缺失说明，不保存完整用户工作流，也不会自动删除或重发。相同turn不同文字拒绝覆盖。可选audit仅存事件/用量/决策，不复制全部聊天正文。

`isolated_test=true`才允许test_limits替换阈值，专供隔离小读数测试；日常配置无此字段，始终用400k/475k/50k。它不是实际堆满长上下文的证据。

官方接口依据：[OpenAI Hooks文档](https://learn.chatgpt.com/docs/hooks)。提交阻止、压缩后停止和诊断事件的能力按文档设计，实际支持程度以本阶段core试验及桌面证据区分。当前未全局启用，新的桌面UI和真实长对话跨线仍需试用，不能把回环假模型当真实模型质量或费用测试。
