# 提炼示例

示例说明信息职责，不要求在正文逐条复制这些解释。

## 偏好与项目分工

原文：“以后帮我做项目，需求和方案先讨论确定，经我同意后开发。”

提炼：“用户的工作习惯是先讨论确定需求和方案，经同意后再开发。”

原文：“这个A项目聊天只做验收，另一个聊天负责开发。”

提炼：“A项目当时由本聊天验收、另一聊天开发。”

前者保留用户明确的习惯，后者保留原分工；读者在B项目的任务由当前请求决定。“不能未经同意就开发”有依据时可以保留，不按句式判错。

## 没有待办的沉淀

原文：“对照表已完成，字段含义和记录身份方法以后还用得上。”

接手保留其完成状态、关键字段含义、方法的理由与适用条件、材料入口；本阶段没有再提起它，也不构成删除理由。历史失败及验证局限保留到理解结论所需的程度。

## 同一压缩阶段多次整理

本阶段从U01开始。第一批整理到U20，发布阶段001和累计接手。聊天继续至U35，第二批仍整理U01—U35，经双检查与用户放行后更新阶段001和接手，上一稿保留备份。若在U40压缩而没有再整理，阶段001的实际截止仍是U35；U36—U40不能算已经保存。下一阶段按新压缩边界确定，旧尾段如需补录，说明来源及缺口。
