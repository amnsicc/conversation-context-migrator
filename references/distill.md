# 蒸馏当前对话

## 开始前

1. 确认当前对话宿主工作区根目录。它拥有新单元和索引。
2. 输出写入目标预览：宿主工作区、目标目录、目标索引、计划单元路径、外部继承来源。
3. 若写入位置偏离宿主工作区、宿主不明确或存在多个合理位置，停止并询问。
4. 同一项目不支持并发蒸馏。用户说明正在并发、迁移目录刚被其它对话更新，或执行中发现索引变化时，停止并要求串行重试。

## 蒸馏范围

- 默认只蒸馏当前对话尚未蒸馏且对后续理解、判断或讨论有用的内容，包括用户指定内容、短期进展、失败尝试和未验证推断。
- 用户说“蒸馏全部上下文”时，覆盖当前可访问历史中的有用内容；不机械记录闲聊或重复确认。说明实际覆盖范围，不把不可见的早期历史称为已完整蒸馏。
- 必须保留用户明确规则、纠正、关键决策、产出物、事实边界、实际继承关系和后续检索关键词。
- 当前任务下一步只作为背景和检索条件记录，不把单元写成待办交接单。

## 对话身份

- 首次蒸馏：创建稳定 `对话标识`，从最新索引分配项目内下一个对话编号。
- 后续蒸馏：只有当前线程已明确持有完全相同的 `对话标识`，或用户明确指定，才继续原对话并增加片段序号。
- 不得依据主题、文件、内容、时间接近或新出现的相似单元判断为同一对话。
- 身份不确定时询问用户；不得认领其它对话单元。

## 串行写入流程

1. 读取最新索引并记录其文件状态；没有索引时准备创建最小索引。
2. 按 runtime-state.md 读取当前线程状态，核对已有单元及最后锚点。锚点必须对应可见消息或原始会话记录位置；无法定位时询问范围，不猜测分界。只提炼锚点后的有用新增内容。
3. 没有实质新增内容时不创建重复单元。
4. 在真正写入前再次检查索引状态。状态变化表示可能存在同项目并发蒸馏：停止，不写入。
5. 创建具有唯一单元标识的新单元。**不要把创建单元与更新索引绑在同一个可能整体失败的补丁中。**
6. 单元成功落盘后，重新读取最新索引，只追加或更新当前单元所需条目，不删除其它对话条目。
7. 索引更新冲突或失败时，不猜测、不覆盖；保留已创建单元，报告“单元已创建但索引未登记”，后续可从目录恢复。

## 链接

- `继续自`：同一对话的上一个增量单元。
- `继承自`：自上次成功蒸馏以来实际读取、尚未登记的所有单元，涵盖此前调用和多轮聊天；从账本取得来源及范围，不限于蒸馏这条消息。部分读取在关系说明中写明范围。
- `纠正了`、`替代了`、`汇总了`：仅在真实发生对应关系时使用。
- 新单元只指向已存在旧单元；禁止自链接。

## 写后验证

报告成功前逐项验证：

```text
新单元文件存在
单元标识与计划一致
单元绝对路径真实且位于宿主工作区
所属项目等于宿主项目
对话标识与当前对话精确一致
项目索引包含当前单元标识和真实路径
索引未丢失其它已存在单元
```

任一项失败，不得报告蒸馏成功，并明确区分：

- 单元未创建；
- 单元已创建但索引未登记；
- 索引冲突，需串行重试；
- 对话身份无法确认。

完成后报告对话编号、对话标识、新单元绝对路径和索引绝对路径。

写后验证成功再运行 `finalize` 登记锚点和已消费的读取记录。若失败，保留原单元并报告“蒸馏已落盘，状态登记待修复”；重试同一单元不重复消费记录。已配置 Obsidian 时再同步，同步失败独立报告。
