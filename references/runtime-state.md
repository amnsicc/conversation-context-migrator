# 读取账本与锚点

使用本 skill 的 `scripts/context_graph.py`，Python 3.10+，只需标准库。项目和线程标识必须是当前宿主和稳定对话标识，不得使用被继承单元的身份。

## 读取状态

```text
python <skill>/scripts/context_graph.py status --project <宿主项目> --thread <当前对话标识>
```

返回 `last_distill` 和 `reads`。`distilled_into` 为空的读取是待写入下一个蒸馏单元的来源；已有值的通过该单元及继续自链追溯。持久化记录不代表正文仍在当前上下文里。

## 实际读取后登记

```text
python <skill>/scripts/context_graph.py record --project <宿主项目> --thread <当前对话标识> --unit <实际读取的单元绝对路径> --scope <实际范围> --event-id <本次读取事件唯一标识>
```

- `scope` 写“全文”、准确章节名或行号区间；多次补读各记范围，不把读过一段标成全文。
- 每次实际读取使用新事件 ID；同一次工具结果的登记重试复用 ID，不会重复登记。它不是批准标识，不能在预检时提前创建事件。
- 脚本记录当前 +08:00 时间、源文件状态、来源身份。工具失败后仅登记实际返回且读到的部分。
- 脚本读取整个源文件用于元数据和哈希维护，不意味着当前对话继承其全文。
- 跨调用和多轮聊天保留账本。尚未蒸馏时不生成图谱节点；可用 `status` 查看待登记事件。
- 登记失败时保留本轮实际读取清单并报告，先重试登记，不丢弃继承关系。

## 蒸馏后登记

根据 pending 读取生成继承自链接；同一来源多次读取可合并为一条链接，在说明中列明范围。旧线程首次升级时从精确匹配的最新历史单元核对锚点和继续自关系，不能因为 JSON 账本不存在就当作新对话。

单元与索引写后验证成功后：

```text
python <skill>/scripts/context_graph.py finalize --project <宿主项目> --thread <当前对话标识> --unit <新单元绝对路径>
```

规则 3.3 的“全部”单元还须传 `--host-thread <当前真实宿主线程ID>`，并提供 schema.md 中的历史覆盖字段。`finalize` 会验证原始日志快照、结束用户消息、全部片段回执及压缩/重叠/缺口复核；失败时不推进 `last_distill`。详见 history-recovery.md。普通增量和旧单元保持兼容，不据此把旧覆盖状态自动升级为完整。

脚本检查身份、锚点、索引登记、待登记来源及既有状态中的继续自关系，再将读取关联到新单元，不修改单元原文。历史继承没有原始事件记录时保持未知，不虚构事件时间。

若遇到遗漏，修正当前新单元或确认身份后重试；历史单元原文不批量修改。此步骤和 Obsidian 同步失败各自报告，不撤销已落盘的产物。
