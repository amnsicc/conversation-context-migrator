# 选择性继承

## 固定流程

```text
理解当前意图
-> 只读轻量索引和目录元数据
-> 提交三档读取预检
-> 停止并等待批准
-> 按批准范围读取
-> 登记实际继承单元
-> 提交继承确认
```

预检前不得读取上下文单元正文、来源文件或为判断而追加的正文。用户明确指定的迁移单元必须进入全部三个档位；批准并实际读取后才算继承。

调用开始时确认当前线程的稳定对话标识和项目内预登记候选编号；当前线程尚无身份时创建预登记对话标识，但尚未蒸馏时不写索引，正式编号在蒸馏时按最新索引确认。不得沿用入口单元的对话身份。

## 选择范围

从当前意图推导材料价值。优先候选：

- 用户指定入口；
- 与当前主题、规则、纠正、文件或关键判断直接相关的单元；
- 高相关直接链接；
- 明确纠正、替代或汇总相关历史的单元；
- 对关键结论必要的来源文件。

通常跳过无关历史、重复背景和已被更权威材料覆盖的内容。达到足够背景后停止，不无边界遍历整个项目或单元图。

## 三个累加档位

```text
保守档 ⊆ 推荐档 ⊆ 充分档
```

- **保守档**：最低充分范围，省额度优先。
- **推荐档**：Codex 推荐的可靠性与额度平衡范围。
- **充分档**：当前意图下最充分的相关证据，不等于全项目全读。

三个档位可以相同；不要为了展示层级添加低价值材料。读取深度可使用：仅确认存在、浏览结构、定点读取、系统浏览、完整读取。

## 精简预检格式

```markdown
## 继承读取预检
- 预检标识：`预检-...`
- 当前意图：
- 入口单元：
- 预登记对话编号：`候选编号；蒸馏时最终确认`

### 保守档
- 单元：...
- 文件：...
- 能支持：...

### 推荐档（Codex 推荐）
- 在保守档基础上增加：...
- 增加价值：...

### 充分档
- 在推荐档基础上增加：...
- 增加价值：...

### 有意跳过
- ...

推荐执行：推荐档
状态：等待批准；尚未读取任何单元正文或来源文件。
请批准：保守档 / 推荐档 / 充分档，或指定自定义范围。
```

提交预检后立即结束当前回合。

## 批准闸门

有效批准必须发生在当前最新预检之后。`执行保守档 / 推荐档 / 充分档` 或明确自定义范围是有效批准；直接回应当前预检的“确认/可以”默认批准保守档。

以下不是批准，并会使旧预检失效：

- 重复发送任务；
- 再次调用 skill；
- 要求重新开始、忽略此前内容或改变意图；
- 质疑、纠正、追加或删减读取范围；
- 只有旧版单清单，没有当前三档预检。

范围被修改后重新提交三档预检。未经批准不得读取正文。

## 执行与去重

- 仅读取批准范围；范围外必要材料先提交增量清单。
- 实际读取任意单元正文后，立即登记为运行时继承。
- 同一单元只读取一次；跨项目使用“项目根目录 + 单元标识”区分身份。
- 同一路径同状态的文件只读取一次；没有现成内容哈希时，不为去重提前计算哈希。
- 发现断链或冲突时记录，不猜测。

## 继承确认

说明：

- 当前对话预登记编号和身份状态；
- 实际继承的单元；
- 上轮或相关历史的核心主题，以及按时间顺序的主要板块和小点；
- 用户专门设置的规则、明确纠正和花较长时间处理的难点；
- 形成的概念、结论、决策、产物和文件；
- 实际读取与有意跳过的来源文件、对话单元和直接链接；
- 去重、断链、未验证和可靠性边界；
- 当前对话若以后蒸馏，这些实际继承单元将写为 `继承自`。

不要自行决定用户下一步工作。
