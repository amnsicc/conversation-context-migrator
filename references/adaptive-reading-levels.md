# 意图驱动的三档自适应读取

## 目录

- 先推导证据需求
- 三个累加档位
- 读取深度
- 预检展示格式
- 条件补读与用户批准
- 停止与升级条件
- 防止两个极端

## 核心目标

以省额度为默认策略，同时让用户在继承前看到更可靠的可选范围。档位不是固定文件数量，也不是固定任务分类；必须从用户当前意图推导。

## 先推导证据需求

预检前依次判断：

1. 用户接下来要回答、决定、设计或执行什么；
2. 哪些关键判断会影响结果；
3. 每个关键判断需要哪些历史上下文、当前事实或原始证据；
4. 哪些未知可能显著改变结论；
5. 每项材料最低需要读取到什么深度。

每个候选读取项都必须能回答：

- 它支撑哪个关键判断；
- 不读取它会留下什么不确定性；
- 为什么采用该读取深度；
- 它属于哪个档位，从哪个更低档位开始新增。

无法说明价值的材料不要列入任何档位。

## 三个累加档位

三个档位必须满足：

```text
保守档 ⊆ 推荐档 ⊆ 充分档
```

简单任务中三个档位可以相同，或某个更高档没有新增内容。不要为了展示三档而人为添加低价值材料；应说明更高档没有必要扩展。

### 保守档：默认，省额度优先

目标：用完成当前意图所需的最小充分证据，给出带可靠性边界的有效结果。

包括：

- 用户明确要求访问的所有上下文单元；
- 能避免关键误判的最少相关单元和来源材料；
- 必要时对高价值文件进行定点读取，而不是全文读取。

规则：

- 用户未指定档位而只确认时执行本档；
- 若本档只能支持初步结论，预检时必须明确说明；
- 不为了让答案显得完整而增加材料。

### 推荐档：可靠性与额度平衡

目标：覆盖最可能改变结论的证据缺口，是 Codex 根据当前意图推荐的常规选择。

在保守档基础上增加：

- 直接影响关键判断的路线、规则、现状或验证材料；
- 索引中高相关但保守档未覆盖的来源；
- 少量带明确触发条件的补读项。

规则：

- 在预检中明确标为 `Codex 推荐`；
- 说明相比保守档提高了哪些判断的可靠性；
- 优先定点读取和系统浏览，不默认完整读取所有文件。

### 充分档：当前意图下最充分

目标：为当前意图提供最顶级、事无巨细且可核验的相关上下文支撑。

在推荐档基础上增加：

- 与当前意图直接相关的完整历史演进、主要原始证据和当前状态验证；
- 可能推翻或显著修正推荐档结论的材料；
- 为高可靠性结论所需的相关源码、日志、验证记录或跨项目材料。

规则：

- `充分` 仅表示对当前意图最充分，不表示读取整个项目或所有历史；
- 无关材料即使额度充足也必须跳过；
- 列明预计高消耗项及其可靠性收益；
- 能定点验证的材料不机械全文读取。

## 读取深度

每个单元或文件单独指定读取深度：

- `仅确认存在`：只使用目录元数据；
- `浏览结构`：读取标题、目录或文件列表；
- `定点读取`：读取与关键判断直接相关的章节或片段；
- `系统浏览`：覆盖全文主要结构和结论；
- `完整读取`：逐段理解全部内容，仅在确有必要时使用。

档位提高不等于所有材料读取深度都提高。

## 预检展示格式

先展示档位总览：

```markdown
- 预检标识：`预检-YYYYMMDD-HHmmss-中文短主题`

| 档位 | 单元正文 | 来源文件 | 预计规模 | 可支持的可靠性 | 相比上一档新增价值 |
|---|---:|---:|---|---|---|
| 保守档（默认） | ... | ... | ... | ... | ... |
| 推荐档（Codex 推荐） | ... | ... | ... | ... | ... |
| 充分档 | ... | ... | ... | ... | ... |
```

再按累加方式列明：

```markdown
### 保守档内容
...

### 推荐档新增内容
...

### 充分档新增内容
...
```

每项至少包含：

```text
名称或路径 | 类型 | 读取深度 | 支撑判断 | 预计规模 | 选择理由
```

预计规模优先使用索引已有字节数；无法获得时使用 `小 / 中 / 大 / 未知`，不要为估算而提前读取正文。

预检输出后必须停在“等待批准”状态；同一回合不得继续读取任何档位中的正文。

## 条件补读与用户批准

- 三档预检必须先完整展示并生成预检标识；没有三档预检就不存在可批准范围。
- 档位内可以包含条件补读项，但必须写明触发条件。
- 用户批准某档位，等于批准该档位包含的条件补读在触发时执行。
- 条件未触发则不读取，不因已经获得授权而消费额度。
- 超出批准档位的新目标必须重新提交增量清单。
- 用户可混合选择，例如“按保守档，但加入推荐档中的某两个文件”。
- 对话中途当前意图发生变化时，只为新增判断提交新的三档预检；已经实际读取的单元继续属于本轮运行时继承，不重复读取。
- 用户重复任务、再次调用 skill、要求重新开始或忽略此前内容时，旧预检和旧批准全部失效；重新提交三档，不得推断用户批准旧范围。

## 停止与升级条件

达到以下条件时停止读取：

- 已能处理当前意图中的关键判断；
- 主要结论有对应证据；
- 剩余未知不会显著改变结论；
- 继续读取的新增可靠性收益较低。

出现以下情况时在批准档位内触发补读，或申请升级档位：

- 已读材料相互冲突；
- 关键判断仍主要依赖猜测；
- 无法区分历史状态与当前状态；
- 新发现的信息可能推翻当前结论；
- 用户指出遗漏或要求更高可靠性。

## 防止两个极端

防止读得太少：

- 不得忽略索引中已经登记的高相关来源而不给理由；
- 重要结论必须映射到证据或明确标为未验证；
- 目录文件名明显揭示高相关材料时，至少将其列为候选。

防止读得太多：

- 不因“可能有用”读取整个目录、整个项目或整条单元网；
- 不把战略判断自动升级为源码全面审查；
- 不把充分档解释成无边界全读；
- 能通过较浅读取深度回答时，不使用更深读取。
