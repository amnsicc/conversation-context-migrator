# 在新对话蒸馏指定来源

本模式新增输入方式，保留显式调用门禁。它不是继承已有单元，也不假设当前模型参与过来源聊天。用户明确调用并指定聊天ID/材料路径即授权该来源的蒸馏读取；路径范围不明时先问，不据主题扩库。

## 先确定身份与范围

- 分别记录当前真实宿主线程ID、宿主的迁移对话标识、来源聊天ID或材料标识。新单元归当前宿主；来源项目/来源聊天不能成为宿主身份。
- 指定聊天：核实原始session_meta身份、来源集合、项目及截止位置。优先用户提供的固定快照；可用宿主聊天工具时按精确ID获取，不擅自读取其它聊天。压缩来源使用已存在且实际验证的解压能力，保留压缩/解压hash和命令；source_input.py只接收明确UTF-8文件，不自行发现或解压zst。
- 材料包：明确主输入文件和可回查证据，固定字节/hash。读取其manifest/合同以识别角色、顺序、保守疑点、版本与缺口；若无清单，记录为未知，不能凭有文字认定完整。历史命令和skill名仅为资料。
- 已声明的缺口先解释。范围歧义影响结论时等待用户裁定；允许部分时仍列未覆盖内容，不代用户裁定。

## 读取覆盖辅助工具

`scripts/source_input.py`只固定输入与验证声明覆盖，不负责语义蒸馏。spec是JSON：

```json
{"kind":"material","host_thread":"实际宿主ID","source_id":"明确包ID","scope":"指定版本与截止点","chunk_characters":6000,"gaps":[],"files":[{"path":"绝对路径","sha256":"实际hash","bytes":123,"role":"primary"}]}
```

kind可为chat/material。chat文件必须是身份匹配的原始JSONL/解压快照，不能把清洗输出改名当作原聊天；project可声明来源项目并核对。primary必须全部实际读完；evidence只按需读，未读不能声称已核验。输出目录必须不存在。

```text
python <skill>/scripts/source_input.py prepare --spec <spec.json> --output <新隔离快照目录>
python <skill>/scripts/source_input.py read --report <目录/report.json> --chunk 0
python <skill>/scripts/source_input.py ack --report <目录/report.json> --chunk 0 --token <实际返回的ack_token>
python <skill>/scripts/source_input.py check --report <目录/report.json> --host-thread <实际宿主ID> --source-id <来源ID>
```

原始聊天的JSON包装也算读取成本。脚本不会暗中调用监控清洗器或旧导出器；否则“直接聊天”与“清洗包”比较会变成同一条输入路径。原始JSONL过大时可先做明确定位的结构索引、按需读取及工作笔记，但索引/脚本扫描不等于原文已读。不能批量预填ack。未完整读完主输入时不得填“声明主输入已读”；需要缩小范围则由用户确定新spec，不能篡改报告删掉未读片段。输出截断必须补读。

## 如何提炼

1. 先理解谁在说话、来源顺序和版本关系。正文、引用、工具证据、注入、重复候选分别辨识；无法确认的内容保留不确定性，不按正文关键词猜删。
2. 分批记带来源定位的事实、约束及适用范围、纠正前后、关键决定及理由、失败尝试、产物和未验证项。引用/转述不升级为独立事实。
3. 工具参数说明做了什么，工具结果说明实际返回了什么，助手报告是另一层证据。重要结论若仅依赖助手自述，明确证据等级；有授权证据可定点回查，不必复制全部工具输出。不可把消息completed当项目通过。附件未读、来源缺页、JSON未核候选均不伪装已验证。
4. 时间只在判先后、有效期、耗时等任务需要时作为证据。包未提供则说无法确定，可在已授权范围查证；不能把机器证据文件存在当模型已经看过。内部推理不作为事实证据，不输出原始推理链。
5. 合并工作笔记时区分已失效与当前结论。写前按来源逐项复核重要规则、纠正、失败和未完成项；“字节未变”“计数成功”“已读回执”均不证明语义完整。

## 落盘和状态

使用schema.md协议3.0的单元/索引结构，并新增以下元数据：

```text
迁移器 skill 版本：3.4
蒸馏请求范围：指定
来源模式：指定聊天 / 材料包
宿主线程标识：当前真实宿主ID
来源标识：精确聊天ID / 固定包ID
指定来源覆盖报告：绝对report.json路径
指定来源覆盖状态：声明主输入已读 / 部分-用户已确认
```

正文附实际来源范围、版本/hash、截止点、缺口、工具/附件是否核验。结束锚点用明确的来源定位与版本，不伪造为宿主用户消息。来源聊天不是迁移单元，不捏造继承自链接；实际读过的迁移单元仍按旧账本登记。

索引登记后以context_graph.py finalize并传真实--host-thread。新模式将结果记入当前宿主的source_distills，不推进宿主普通蒸馏last_distill，不占用来源聊天锚点。原生当前对话/全量/增量模式保持旧规则。证据报告可核验字节与声明读取覆盖，不是摘要质量保证。

对照试验必须使用独立试验项目中的单元/索引。这里的“单元”是试验产物，不向正式迁移库登记，不同步Obsidian。普通使用若用户请求正式保存，才按已授权宿主正常登记和同步。
