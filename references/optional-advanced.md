# 按需高级规则

普通蒸馏和继承不要读取本文件。仅在实际遇到对应情况时使用。

## 跨项目

- 各项目单元网保持独立；用户指定外部单元或项目时，将高相关外部索引纳入同一张三档预检。
- 新单元仍归当前对话宿主工作区，只更新宿主项目索引。
- 不扫描磁盘寻找所有项目，不默认读取所有已知项目索引。
- 跨项目单元身份使用“规范化项目根目录 + 单元标识”。

## 文件内容去重

- 默认只按规范化绝对路径和已知文件状态去重。
- 只有已存在内容哈希，或用户明确要求深度跨项目去重时，才使用内容哈希合并不同路径的相同正文。
- 不为预检而提前读取文件或计算哈希。

## 旧单元兼容

- 旧单元和旧索引保持原样，能够理解的字段正常读取，缺失字段标记未知。
- 旧索引只有额外章节或旧版本号，但最小身份、路径和链接仍可理解时，不需要读取本文件或执行转换。
- 当前磁盘 3.2 规则优先；旧材料中的 skill 版本只表示历史生成版本。
- 不批量改写旧单元。新单元按 3.0 结构创建，并可链接旧单元。

## 索引健康检查

执行 `/检查索引` 或怀疑索引漏登时：

- 只检查迁移目录、上下文单元索引、单元文件名、索引路径和直接链接；
- 不默认读取所有单元正文；
- 报告单元文件已存在但未登记、索引路径不存在、重复单元标识、断链、循环风险和孤立单元数量异常；
- 如需读取少量单元元数据确认身份，先说明原因和范围；
- 如需修复，先给修复清单，用户确认后再补录或重建。

## 索引重建与孤立单元

当单元已创建但索引未登记，或索引损坏时：

1. 扫描当前项目迁移目录中的单元文件；
2. 读取其最小元数据和直接链接；
3. 重建或补录索引；
4. 不修改单元正文；
5. 验证每个索引路径真实存在。

## 异常关系

- 发现断链、循环或身份冲突时停止该路径并报告，不猜测。
- 很晚才发现的重要关系，用新的关系说明单元记录；不回头改写旧单元。
- 同一项目并发蒸馏造成冲突时，不自动合并对话身份；要求串行恢复。
