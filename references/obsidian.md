# Obsidian 单元关系图

## 数据与展示

- 原项目单元及索引是权威来源；库内生成单向展示副本。完整正文保留 Markdown 内容，原本地链接转为外部文件入口，原文 wikilink 显示为文字，避免误生边；原文件入口提供精确原文。
- 节点全部为单元。对话、话题、事件、索引、报告不生成节点。账本、清单及报告使用 JSON，置于隐藏目录。
- 只对已记录的继承自、继续自生成 **来源 → 后续** 箭头。为适配原生链接方向，在来源展示副本的“传播到”中生成指向后续副本的 wikilink；继承来源及纠正/替代/汇总详情使用 `obsidian://open` 链接，不生成反向或额外边。
- 现有主题标签规范化为 `ccm/topic/...`，用于筛选和配色，不因话题相同创建关系。默认取常见话题前八项分组配色，可在 Obsidian 分组中调整。
- 未蒸馏时只保存读取事件；新单元产生并登记后才有接收方节点及箭头。

## 配置一次，以后自动同步

本机配置：`config/obsidian.local.json`。

```json
{
  "source_roots": ["项目所在的已授权目录"],
  "vault": "已存在的Obsidian库绝对路径",
  "output_folder": "上下文迁移"
}
```

路径是用户的本机选择，不写死到通用算法。其它机器缺少目录时报告需配置，不猜测新路径。

继承完成并登记实际读取后、蒸馏完成并 finalize 后、或用户执行 `/同步图谱` 时：

```text
python <skill>/scripts/context_graph.py sync --config <skill>/config/obsidian.local.json
```

配置范围已经授权用于兼容导出扫描，这类维护读取不属于当前对话背景继承。范围外新项目须先明确纳入，再更新配置。普通同步不更改图谱 UI 设置。

初次接入或用户要求设置图谱时，加 `--configure-graph`：备份原 graph.json，设置专属目录过滤、箭头、隐藏标签/附件节点、显示孤立单元及话题配色。
正在使用该库的 Obsidian 会缓存并覆盖外部设置。脚本检测到活动库时，只准备 `.ccm/graph.pending.json`，报告 `pending_app_close`，不覆盖活动配置。请用户正常退出应用，再重跑同一命令；得到 `applied` 后通知用户重新打开。不要把笔记同步成功当成图谱设置已生效，也不强制关闭用户应用。
未实际查看界面时，不声称界面已通过验收。

预览用 `--dry-run`；报告用 `--report <JSON路径>`。输出包括项目筛选表达式、源哈希、迁入数、边数、未知项和重定位记录。常用筛选：

```text
path:"上下文迁移/" tag:#ccm/unit
path:"上下文迁移/<项目名-根目录短哈希>/单元/"
path:"上下文迁移/" tag:#ccm/topic/java
```

文件夹筛选只显示范围内节点及彼此连线，范围外来源仍可在详情查看。全目录视图可查看跨项目关系。

## 历史兼容与恢复

- 扫描正式“对话上下文迁移”目录中的单元，跳过备份、临时、依赖、Git 目录及符号链接。索引不是节点。
- 解析明确的元数据和关系表，兼容 2.0/3.0，不按文件时间、话题或正文猜测关系。
- 同宿主同 ID 且内容相同的副本去重；内容不一致报告身份冲突，不擅自选一个。
- 旧路径失效但目标 ID 在授权范围内唯一时，可重定位并报告。目标不存在或不唯一只在详情标明，不创建占位节点。
- 不改历史源文件，不补造未知读取时间或范围。自链接、循环关系记录但不画成有效继承边。
- 原生图不区分继承自、继续自线型；具体类型在详情和“传播到”列表可见。
- 同步使用锁、原子替换和重试日志。副本被手改时保留并停止，不覆盖用户内容。源目录不可用、已同步来源缺失或身份冲突时停止，避免悄悄生成不完整图谱。
- 成功须验证全部副本及源文件哈希。结果在 `<输出>/.ccm/last-sync.json`，映射在 `manifest.json`。无变更重跑不改写笔记。
- 失败只报告可视化待重试，已成功的继承/蒸馏保持成功；处理明确错误后重试同一命令。
