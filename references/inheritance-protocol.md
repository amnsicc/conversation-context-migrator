# 单元图选择性继承与双层去重协议

## 目录

- 不可绕过的继承状态
- 两阶段继承
- 继承入口与单元选择
- 防循环与双层去重
- 本轮继承与阅读账本
- 递归范围控制
- 继承确认与质量检查

## 核心原则

从入口单元和一个或多个相关项目索引出发，先根据当前意图制定读取清单，等待用户确认后再选择性遍历单元图。单元和来源文件必须在本次继承范围内统一去重；链接或相关项目很多不代表全部读取。

通过本 skill 实际读取任意上下文单元正文，即表示当前对话运行时继承该单元。读取一个或多个单元、读取全部或部分正文都适用。只读索引、目录和单元元数据用于预检时不算继承。

## 不可绕过的继承状态

```text
版本自检
-> 意图分析
-> 目录预检
-> 三档读取方案
-> 等待用户批准
-> 执行前批准闸门检查
-> 按批准范围读取并登记运行时继承
-> 继承确认
```

- 未获得批准前，不读取单元正文或来源文件。
- 未完成继承确认前，不把依赖历史背景的回答表述为已正式继承后的结论。
- 用户要求访问迁移文件夹中的单元，本身表示拟继承这些单元；仍需预检确认读取范围。
- 当前对话蒸馏时，将运行时继承账本中的单元自动写为 `继承自` 链接。
- 当前对话不蒸馏时，运行时继承随对话结束，不创建持久化链接。
- 当前执行规则版本来自磁盘 `current-version.md` 和当前磁盘 `SKILL.md`；项目索引或目标单元中的版本字段只作为历史兼容信息。
- 声称正在使用当前版本，但没有提交该版本要求的完整三档预检，视为无效执行；必须停止，不能继续读取。

### 当前对话编号

- 调用继承时即从当前对话宿主工作区的项目索引确认已有编号，或计算下一个可用编号并标记为 `预登记`。
- 预登记编号用于当前对话中的识别和报告，不要求立即创建单元或修改索引。
- 当前对话蒸馏时正式写入索引；若编号发生冲突，使用当时下一个可用编号并明确报告调整。
- 外部入口单元所属项目的编号只用于识别外部历史，不得作为当前对话编号。

## 两阶段继承

### 阶段一：目录预检与用户确认

预检阶段只允许读取项目索引、用户提供的目录清单或等价的轻量元数据。不要读取：

- 上下文单元正文；
- 单元登记的来源文件、产出文件、记忆或其它对话材料；
- 为了“判断一下”而临时追加的清单外正文。

根据用户当前意图、索引中的单元目录、直接链接目录、来源文件反向索引和相关目录文件名，按 [adaptive-reading-levels.md](adaptive-reading-levels.md) 提交三个累加档位：

```markdown
## 继承读取预检

- 预检标识：`预检-YYYYMMDD-HHmmss-中文短主题`
- 当前执行 skill 规则版本：
- 目标索引或单元历史生成版本：
- 当前对话编号及状态：
- 当前意图：
- 需要支撑的关键判断：
- 入口单元：
- 计划检索项目单元网：P 个
- 其它索引候选：X 个，其中计划跳过 Y 个
- 目录信息不足或无法预估：

### 档位总览
| 档位 | 单元正文 | 来源文件 | 预计规模 | 可支持的可靠性 | 相比上一档新增价值 |

### 保守档内容（默认）
| 所属项目 | 名称或路径 | 类型 | 读取深度 | 支撑判断 | 预计规模 | 选择理由 |

### 推荐档新增内容（Codex 推荐）
| 所属项目 | 名称或路径 | 类型 | 读取深度 | 支撑判断 | 预计规模 | 选择理由 |

### 充分档新增内容
| 所属项目 | 名称或路径 | 类型 | 读取深度 | 支撑判断 | 预计规模 | 选择理由 |

### 有意跳过的范围
| 范围或代表项 | 数量 | 跳过理由 |
```

`候选来源` 区分：

- 指定入口；
- 入口链接范围；
- 全项目索引中发现的未链接候选；
- 用户补充指定。

所有用户明确要求访问的上下文单元必须进入三个档位。其它候选根据当前意图和证据价值分档，不使用固定文件数量。

读取深度使用仅确认存在、浏览结构、定点读取、系统浏览或完整读取。清单中的数量以索引现有信息能够确认的跨项目去重结果计算；内容相同但路径不同的文件要列出别名路径和所属项目。预检阶段不为计算新哈希而读取来源文件。索引缺失、过时、没有文件哈希或无法列出文件时，明确标为未知，不用猜测补齐。

提交预检后停止，等待用户选择档位、删减、追加或调整。用户未指定档位而只回复“确认”“可以”等时，执行 `保守档`。用户修改清单后重新计算数量并再次提交；确认前不得开始正文继承。

预检回复末尾必须明确输出：

```text
状态：等待批准；尚未读取任何单元正文或来源文件。
请批准：保守档 / 推荐档 / 充分档，或指定混合范围。
```

提交该回复后立即结束当前回合；不得在同一回合继续调用工具读取正文、执行 Git 状态检查或给出依赖历史材料的正式结论。

### 有效批准与预检失效

只有满足以下全部条件，才算有效批准：

1. 批准发生在当前最新且仍有效的三档预检之后；
2. 用户明确选择 `保守档`、`推荐档`、`充分档`，明确指定混合范围，或直接回应当前预检说“确认”“可以”等；
3. 用户消息中没有要求重新使用 skill、从零开始、忽略此前内容、重新预检、改变当前意图或替换读取范围；
4. 被批准的是当前版本生成的三档预检，不是旧版单清单。

以下情况绝不能推断为批准：

- 用户重复发送原始任务或完整指令；
- 用户再次调用本 skill；
- 用户说“重新使用”“从零执行”“忽略之前使用后的内容”“作废之前结果”；
- 用户提出问题、纠正、补充新意图或要求重新评估；
- 线程中只有旧版单清单，没有当前版本三档预检；
- Codex 认为用户“大概就是同意了”。

发生上述情况时：

1. 当前旧预检立即失效；
2. 不读取任何单元正文、来源文件或执行状态检查；
3. 根据最新意图重新生成三档预检和新预检标识；
4. 再次等待明确批准。

用户修改三档内容后，原预检标识失效；重新提交完整更新版三档预检并生成新标识。

批准判定示例：

| 用户消息 | 判定 | 动作 |
|---|---|---|
| `执行推荐档` | 有效批准 | 执行当前有效预检的推荐档 |
| `确认` | 条件有效 | 仅当直接回应当前有效三档预检且没有其它语义时，执行保守档 |
| `按保守档，但加入文件 A` | 修改范围 | 重新提交带新标识的完整三档预检，等待批准 |
| 重复发送完整原始任务 | 不是批准 | 作废旧预检，按最新任务重新提交三档 |
| `重新使用这个 skill，忽略之前使用后的内容` | 明确重置 | 作废旧预检和旧批准，重新提交三档 |
| `你确定不用读文件 A 吗` | 纠正或质疑 | 不读取；重新评估并提交新三档 |
| 当前线程只有旧版单清单，用户再次调用 skill | 不是批准 | 丢弃旧单清单，按当前版本提交三档 |

### 执行前批准闸门

读取任何单元正文、来源文件或执行超出轻量目录预检的状态检查前，必须逐项确认：

```text
当前磁盘版本已确认
当前最新预检是三档格式
当前最新预检标识仍有效
用户在该预检之后明确批准了档位或混合范围
批准消息不包含重置、重新执行、新意图或修改范围
即将读取的目标属于批准范围或已触发的条件补读
```

任一项不满足就停止并重新预检。不得把旧版单清单、历史批准、重复任务或模型推断当作授权。

### 阶段二：按批准清单执行

通过执行前批准闸门后，仅读取批准档位中的单元和来源文件。读取上下文单元正文时立即将其加入运行时继承账本。执行中若从已批准单元正文发现新的必要单元或文件：

1. 新目标已作为批准档位的条件补读项，且触发条件成立：直接读取并记录触发原因；
2. 新目标超出批准档位：不直接读取，提交增量读取清单；
3. 说明为什么目录预检时没有发现以及它可能改变哪个判断；
4. 等待用户再次确认后再读取。

用户指出少看了某个上下文单元时，将其加入增量读取清单；实际读取后它同样成为本轮继承单元。用户认为某项不应读取时，将其移除。一次确认只授权所选档位及其中明确列出的条件补读，不等于授权读取整条链接支路或整个项目。

当前意图在对话中途变化时，只为新增判断重新提交三档预检。此前已经实际读取的单元继续属于本轮运行时继承，不重复读取或撤销。

## 继承入口

1. 用户要求访问一个或多个迁移单元：在预检清单中将这些单元全部列为拟继承入口，并纳入所有档位；确认前不读取其正文。
2. 用户只提供项目：先检索 `<项目根目录>\对话上下文迁移\上下文单元索引.md`。
3. 当前对话已经继承过单元：优先考虑已继承单元，但仍按当前意图检索项目索引中的其它候选。
4. 当前对话没有继承单元：直接按当前意图检索项目中的所有候选单元。
5. 跨项目需求：按 [cross-project-discovery.md](cross-project-discovery.md) 发现并分别检索高相关项目索引，合并成一张预检清单，不合并项目单元网或无关历史。

用户说明当前准备做什么或正在做什么通常只是检索条件。除非明确要求执行，否则继承完成后只提交理解确认。

## 单元选择

优先列入读取档位：

- 用户明确指定的入口单元；
- 与当前主题、文件、模块、规则或纠正直接相关的单元；
- 当前入口单元通过高相关链接直接指向的单元；
- 明确纠正、替代或汇总当前相关历史的单元；
- 产生了当前工作依赖文件或结论的单元。

通常跳过：

- 与当前意图无关的单元；
- 已被更权威的汇总或替代单元覆盖，且不需要原始证据的单元；
- 只有重复背景、没有新增事实的单元。

## 简单防循环与异常图处理

正常单元创建规则已经保证新单元只指向旧单元，因此不会产生循环。

遍历时仍维护：

```text
visited_units：本次已读取的单元标识
active_path：当前递归路径中的单元标识
```

处理规则：

1. 目标单元已在 `visited_units`：不重复读取，只合并新的到达理由。
2. 目标单元已在 `active_path`：发现循环或异常旧数据，立即停止该路径并记录。
3. 目标路径不存在或单元标识不匹配：记录断链，不猜测内容。
4. 链接相关性低：停止沿该链接继续展开。

## 单元级去重

单项目内稳定单元标识是主要去重键。跨项目使用“规范化项目根目录 + 单元标识”，避免不同项目使用相同标识时误合并。

例如：

```text
A -> B
A -> D -> B
E -> A
E -> B
```

从 `E` 检索时，`A` 和 `B` 即使经多条路径到达，也各读取一次。新的路径只补充：

- 为什么它与当前意图相关；
- 经由哪些链接到达；
- 是否需要提高或降低相关性。

### 语义重复但 ID 不同

不同单元可能形成相似结论。不要删除历史单元，按以下顺序选择：

1. 明确 `汇总了`、`纠正了` 或 `替代了` 旧内容的单元；
2. 与当前意图更直接相关的单元；
3. 事实依据更可靠的单元；
4. 更新且仍有效的单元。

其它相似单元保留为证据，除非需要核对演进过程，否则不重复展开。

## 来源文件级去重

维护：

```text
visited_files：规范化绝对路径 + 文件状态
visited_content：内容哈希
```

路径规范化：

- 解析为绝对路径；
- Windows 下按大小写不敏感比较；
- 统一目录分隔符；
- 不因文件名相同认定是同一文件。

文件状态优先使用：

1. 内容哈希；
2. 版本号或提交标识；
3. 最后修改时间与大小；
4. 无法获得时标记为 `未知`。

读取规则：

- 同一路径同状态只读取一次；
- 同一路径状态变化后，可读取新版本一次；
- 跨项目共用同一份 `visited_files` 和 `visited_content`；
- 不同路径内容哈希相同时正文只读取一次，但保留全部路径、所属项目和用途；
- 没有内容哈希时，不因文件名、相对路径或项目相似而合并；
- 多个单元引用同一文件时，合并读取理由；
- 当前意图只需要知道文件存在时，不必读取正文；
- 迁移单元中的历史文件结论与当前文件状态冲突时，明确区分历史与当前事实。

## 本轮继承与阅读账本

在本次调用内部维护：

```text
运行时继承单元
已读取单元
已跳过单元及原因
已读取文件及状态
内容相同但来自不同项目的文件别名路径
已系统浏览或定点读取的文件
发现的断链、循环或版本不兼容
```

当前对话蒸馏时，运行时继承单元必须转为新单元的 `继承自` 直接链接。其它阅读账本内容只有在影响后续理解、暴露遗漏或形成纠正时才进入新单元。

## 递归范围控制

- 优先入口单元和直接链接。
- 只有高相关链接继续递归。
- 项目图较小时可以扩大读取范围。
- 达到足够背景后停止扩展。
- 用户指出遗漏时，再使用缺失主题扩大检索。
- 不因“可能有用”读取整个图。
- 链接范围外的单元如果与当前意图相关，可以从全项目索引列入清单。
- 入口单元存在链接不代表整条支路获得读取授权。
- 批准档位内的条件补读按触发条件执行；任何档位外扩展都先提交增量读取清单并等待确认。

## 继承确认

确认报告动态说明：

- 当前对话编号和对话标识；
- 实际继承的入口单元与其它单元；
- 本轮运行时继承将在当前对话蒸馏时持久化为 `继承自`；若不蒸馏则不会创建链接；
- 从不同单元继承到的背景、规则和纠正；
- 实际读取或跳过的来源文件；
- 因去重未重复读取的单元或文件；
- 发现的断链、循环、旧格式或未确认内容。

不要自行安排下一步。

## 继承质量检查

- 是否理解当前意图；
- 是否完成当前磁盘版本自检，并区分当前执行版本与历史产物版本；
- 是否把当前意图拆成关键判断并使用三档自适应读取；
- 是否为三档预检生成预检标识，并在执行前通过严格批准闸门；
- 是否拒绝把重复任务、重新使用、从零开始或忽略此前内容解释为批准；
- 是否拒绝批准或执行旧版单清单；
- 是否报告当前对话编号及登记状态；
- 是否检索项目索引，而非只看一个入口的祖先；
- 跨项目时是否只发现和检索高相关项目索引，而非读取所有已知项目目录；
- 是否在读取单元正文和来源文件前提交去重后的读取清单并获得确认；
- 是否将用户要求访问的所有上下文单元纳入每个档位；
- 是否将任何实际读取的上下文单元正文登记为运行时继承；
- 是否区分入口链接候选与全项目索引中的未链接候选；
- 是否在发现清单外必要材料时暂停并申请增量确认；
- 是否使用 `visited_units` 防止重复单元读取；
- 是否使用 `active_path` 防止异常循环；
- 是否使用 `visited_files` 防止来源文件重复读取；
- 是否使用内容哈希避免跨项目不同路径的相同正文重复读取；
- 是否按需停止递归；
- 是否区分历史结论与当前文件状态；
- 是否说明实际读取和有意跳过的范围。
